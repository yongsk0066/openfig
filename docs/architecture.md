# Architecture

## Input to suggestions

```text
zsh / fig.zsh → local hook socket → Rust desktop → WKWebView delivery
                                                  ↓
                                   completion model → React list
                                                  ↓
                              epoch/revision checked insertion → zsh
```

The shell owns its edit buffer and applies revision-checked insertions. The desktop owns native windows, accessibility, session-scoped keyboard interception and shell connections. The WebView owns parsing, generation and selection; React renders that state. Settings use a separate WebView. The zsh hook uses one owned scheduler entry for reconnect/backoff and ZLE descriptor readiness for the bounded, partial-safe greeting. A timeout retries; explicit protocol refusal disarms. Reconnection restores context before the current edit snapshot, keeping revisions monotonic and clearing old interception/acknowledgement state. Connection syscalls remain local synchronous operations. A single bounded incremental reader handles post-handshake frames across socket callbacks, key replies and prompt cleanup; incomplete frames return to ZLE without blocking typing. Frames are capped at 1 MiB, and unrelated messages cannot renew a key verdict deadline. A partial or absent greeting also never blocks the editor.

`packages/autocomplete-app/src/fig/services.ts` is the completion composition root. It injects process, filesystem, spec import, history, settings, storage, clock and effect adapters into core factories. `state/model.ts` owns completion transitions; `parser/coordinator.ts` suppresses superseded parse results. Parser/spec factories live under `packages/autocomplete-parser/src/`. Cores must not acquire React, desktop adapters or browser globals. `scripts/check-architecture.mjs` checks designated roots and their transitive workspace dependencies; it conservatively checks nondeterministic access as well, but does not prove whole-program determinism.

The native `ApplicationServices` owns shared backend services, the settings notification bus and the icon response cache. Watchers subscribe through this owner and stop when it is dropped; immutable bundled assets remain shared. `EventSender` is the main-loop command port. `WebviewManager` owns `PlatformState` directly. Its `MainThreadMarker` keeps native observers, window state and activation policy on the main thread. Workspace callbacks enqueue owned identities; they never borrow the observer registry. AX callbacks borrow their payload immutably. Subscription guards own retained block tokens and unregister on drop. AX handles live in supervised `fig_native_worker` child processes; only owned identities/results cross inherited pipes. Activation, caret, focused-window, text-focus and window-frame lanes each keep at most one active query and one latest pending request. AX notification callbacks enqueue identities without querying their elements. Results are checked against PID, window ID and focus generation; caret results also require the current foreground application. Frame caches belong to a focus generation, so native placement reads cached bounds rather than synchronously querying WindowServer. Native calls remain non-preemptible within a process; the desktop can terminate their process.

Official Ghostty support uses an InputMethodKit palette helper to query the focused text client for caret geometry. It exchanges bounded, correlated scalar replies over a user-private socket with peer-UID and message validation. This trusts the local user; it does not authenticate the helper executable by code signature. The terminal binary and normal keyboard input source remain unchanged. The popup uses `orderFrontRegardless` for nonactivating presentation; it must not steal terminal focus. See [input-method installation](macos-input-method.md). `input_method_recovery::Coordinator` owns the palette selection lease and bounded recovery policy. Transport readiness, graceful retirement and verified foreground-client attachment are distinct; helper replacement preserves popup intent while revalidating geometry. Recovery can proceed without a new key or visible list, and never changes the normal keyboard source.

Only the popup root opts into synchronous DOM layout measurement on commit. This prevents an old zero-size observation from hiding the window while hidden WebKit defers subsequent ResizeObserver callbacks. Other size observers remain asynchronous.

Focus generation determines cache validity, not when frames refresh. Focus changes and shell edits request fresh bounds; visible popups also use the adaptive frame poll described below. Pure window translations reuse a verified IMK caret relative to its owning window; edits, scrolling, focus changes and resizes invalidate that anchor. Screen-coordinate replies arriving during motion cannot overwrite the translated anchor. IMK requests pause while mouse buttons are held or movement is recent, resuming after release and 150ms without movement; no global keyboard monitor is used. Missing geometry suspends presentation while preserving the current list intent, retrying at 250ms while hidden. Actual dismissal or focus change clears that intent. Polling and native query delays mean these intervals are not freshness guarantees.

## Consistency and lifetimes

| Boundary | Contract |
| --- | --- |
| Page reload | Page epochs reject effects and acknowledgements from obsolete WebViews. Runtime hello/ready and ACK/NACK coordinate delivery and resynchronization. ACK does not prove parsing, DOM commit or pixel presentation. |
| Input | Session and input revision distinguish edits. Parse/generator cancellation and generation checks prevent old results overwriting current state. |
| Shell insertion | Versioned edit messages carry expected revision; the shell accepts a matching edit or rejects it. |
| Catalog cache | Spec-source/index cache shared within the completion owner; bundled files are local. Execution-cache expiry does not clear catalog imports. |
| Execution cache | Bounded scopes keyed by session, cwd, environment and spec-source settings. A non-sliding 60-second lifetime uses an injected monotonic clock. Expiration replaces the loader and dependent parser/spec caches together; late work stays in the old generation. Version requests share in-flight work separately from input cancellation. |
| Parser cache | Execution generation plus parser-relevant settings; cosmetic changes do not invalidate command facts. Owner clear/reload clears scopes and the catalog. |
| Geometry | Latest pending caret geometry is merged per event-loop turn; size requests consume it immediately. Hide/show and dry-run behavior remain explicit. |
| Disposal | Completion owner aborts work, disposes model subscriptions and flushes recency persistence. |

Filesystem listing returns an array of names, preserving embedded newlines and optional directory suffixes. It has no persistent directory cache. External generator hosts retain the command-based fallback.

The application-owned I/O service runs directory enumeration and generator commands in disposable `fig_io_worker` processes. Even cwd canonicalization, symlink classification and command startup happen in the child. Command admission is 32 requests with four running; directory admission is eight with two running. Excess requests fail immediately. The deadline includes queueing: at most 60 seconds for commands and five seconds for directories. Cancellation or timeout kills the entire process group; permits return only after reaping, so stalled work cannot create unbounded replacement processes. A child-side parent watch kills the group if the desktop exits. This is fault containment, not a sandbox for untrusted generators; a command deliberately detaching from its process group is outside the contract.

Each I/O request uses a fresh child and inherited, length-prefixed JSON pipes (1 MiB request, 16 MiB reply). Output is limited to 1 MiB per command stream; directories fail explicitly above 65,536 entries or 1 MiB of names. Fresh processes cost startup time; measure that overhead with the backend benchmark rather than assuming isolation makes successful requests faster. File read/write APIs and SQLite remain separate in-process services; this does not claim all filesystem calls are isolated.

Local CLI IPC admits 32 same-user connections and hook IPC 128. The listener owns connection tasks; hook connections own their writer, command tasks and session registration. Dropping the owner closes these resources. New clients have five seconds to greet; established idle subscriptions remain valid. Protobuf frames are capped at 16 MiB with a five-second partial-frame deadline that survives cancellation of a receive future. Malformed connections are retired rather than resynchronized through arbitrary payload bytes. Protobuf request/response and native WebView delivery have distinct roles; see [protocol schemas](../proto/README.md).

Each process owns one mutex-protected SQLite connection. WAL setup retries only transient busy errors with a total five-second budget. Schema migration and read/modify/write state operations reserve the writer before reading, preventing deferred-transaction lock upgrades from failing or losing updates across processes. Ordinary reads retain WAL concurrency.

## Native safety and remaining boundaries

`macos-utils` denies implicit unsafe operations inside unsafe functions. `ApplicationServices` owns the isolated icon lane: at most eight admitted requests and one child process. AppKit rendering runs on that child's main thread, never through a desktop icon event. Callers wait up to two seconds; canceled queued work is skipped and permits are released after handling. Resolved bytes retain the 512-entry FIFO; timeout/overload fallbacks are not cached. Path metadata lookup also stays in the child; unavailable path icons use the trailing slash as a folder hint rather than submitting uncancelable filesystem work on the desktop runtime.

The shared supervisor bounds frames to 1 MiB, verifies request IDs, response types and geometry, and retires partially read/canceled connections. Geometry/AX queries have a 750ms deadline; icon queries have 1.5s. Timeout, EOF or malformed output kills the child and waits up to 500ms for reaping. A replacement is never started until exit is confirmed. Latest-only lanes retry without another input with bounded backoff; closing an owner cancels active work. A child-side parent watch exits orphaned helpers even if their main thread is stuck. Each of the six lanes owns at most one child, launched lazily from the signed bundle. There are no listening sockets or external executable selectors on this protocol.

- **FFI:** remaining unsafe code covers retained Core Foundation values, typed out-parameters, notification callbacks and Objective-C method overrides. Enrollment uses public TIS APIs; separately, `_AXUIElementGetWindow` remains private SPI, and vendored accessibility bindings still rely on native attribute/type contracts. Compiler checks do not prove those ABI assumptions.
- **Native latency:** isolated query/icon stalls cannot occupy the desktop main thread indefinitely or permanently consume that lane's permits. A kernel that cannot reap a killed child leaves that lane degraded and periodically checked, rather than spawning unbounded replacements. This is process fault containment, not a guarantee against an OS-wide WindowServer failure. AppKit window operations and AX observer registration/teardown still belong to the desktop main loop; they are separate native boundaries, not covered by query-process deadlines. See [latency diagnostics](latency.md); ACK and RAF are not pixel-presentation timestamps.
- **Cache freshness:** expiration is checked on the next scope lookup, not by a timer or filesystem watcher. The 60-second lifetime is a bounded-staleness policy, not immediate detection of version-manager changes. Catalog source changes still require owner clear/reload.
- **Validation:** automated checks cover ownership, stale results, cancellation, geometry and WebView lifecycle. Each release still needs terminal regression checks; prior runtime results do not validate a changed build. Permission prompts require separate live validation from mocked installer tests.

React is the current presentation adapter. The injected core permits another UI, but a Web Components/native rewrite has no demonstrated benefit from current measurements. Keep the current boundary until profiling identifies a rendering bottleneck.

Window-frame polling runs at 4 Hz while a visible list is stationary, increasing to 20 Hz during mouse drag or for 500ms after a frame change. AX move/resize notifications also request a frame immediately. The timer sleeps while tracking is disabled, and at most one tick waits in the main queue. IMK refresh cadence and stale-result validation remain independent.

## macOS automatic startup

`login_item.rs` manages automatic app startup when the user signs into macOS, separating reconciliation policy from the macOS backend. Settings notifications request reconciliation on the main loop; persisted applied intent prevents repeated registration and preserves OS-side user decisions. Pending approval is distinct from enabled. Legacy cleanup follows confirmed registration and intent persistence, and never unloads the running desktop. Development/staged bundles cannot mutate the installed login item. These low-frequency ServiceManagement calls remain native main-loop operations, outside the query-worker deadlines.
